只输出以下两个部分，不输出 Markdown 代码围栏或额外说明。

[BOTTLENECK_JSON]
{
  "reasoning": ["<正式指标→bottleneck>", "<直接原因 evidence→cause>"],
  "evidence": [
    {
      "evidence_key": "<原始指标或源码事实 key>",
      "source": "<performance 精确字段或 op_host/op_kernel 相对文件::符号>",
      "observation": "<当前输入中的客观观察>"
    }
  ],
  "bottleneck": {
    "bottleneck_key": "<本轮首选受限位置>",
    "cause_key": "<中粒度可行动根因>"
  }
}

[STRATEGY_JSON]
{
  "reasoning": ["<cause_key→strategy_key>", "<cause evidence key+source→targets+operation；不复制observation>"],
  "strategy": {
    "strategy_key": "<cause 唯一映射的策略>",
    "actions": [
      {
        "target": "<输入源码中真实存在的 相对文件::符号>",
        "operation": "<strategy 唯一对应的稳定代码变换>",
        "edits": ["<1–4 条 target symbol 内的可定位源码对象+明确变换+必要参数>"],
        "constraints": ["<1–4 条 dtype/索引/tail/容量/同步/ABI/数学语义不变式>" ]
      }
    ]
  }
}

每次最多输出一个 bottleneck、一个 cause 和一个 strategy；非空 bottleneck 的 evidence 限 2–4 条，bottleneck=null 时 evidence=[]。两个 reasoning 各自只完成一次推断，actions 限 1–4 项。每条 edit 写成“源码对象：明确变换；必要参数”，不得只翻译 operation；constraints 只写不变式，action 不引用 performance 字段或收益。不要重复通用优化知识；不得输出候选项、收益预测或输入中不存在的证据、文件、符号和 API。
